# ملاحظات ربط Supabase لاحقًا

هذه الحزمة لا تنفذ أي اتصال بقاعدة بيانات. لا تشغّل SQL على مشروع Dina's Corner قبل مراجعة المخطط الحالي والنسخة الاحتياطية.

## التصميم المقترح
- استخدام Supabase Auth للمصادقة.
- إنشاء ملف نشاط `businesses` بمعرّف مستقل لـ GRAND DRY CLEAN.
- ربط جداول الخدمات/الأصناف بمعرّف النشاط `business_id`.
- فرض سياسات RLS بحيث لا يرى حساب المغسلة إلا سجلات نشاطه.
- لا تنشئ كلمة مرور داخل جدول عادي ولا تخزنها كنص صريح.
- إذا كان تسجيل الدخول باسم مستخدم بدل البريد، نحتاج آلية آمنة على الخادم لتحويل اسم المستخدم إلى هوية Auth؛ لا تضع مفاتيح service_role في JavaScript بالمتصفح.

## قبل الربط
نحتاج أحدث ملفات Dina’s Corner ومخطط الجداول وسياسات RLS الحالية. بعدها نحدد هل نضيف جداول مستقلة أم نوسع الجداول الموجودة، من غير التأثير على بيانات دينا.

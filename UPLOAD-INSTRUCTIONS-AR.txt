تعليمات رفع نسخة POAC إلى GitHub

1) افتح المستودع الصحيح على GitHub أو استخدم GitHub Desktop لعمل Clone له.
2) احتفظ بنسخة احتياطية من الفرع الحالي قبل استبدال الملفات.
3) انسخ محتويات مجلد poac-main إلى جذر المستودع، بحيث تظهر الملفات welcome.html وmenu.html وindex.html مباشرة في الجذر، وليس داخل مجلد poac-main إضافي.
4) حافظ على المجلدات كما هي: assets/ وdata/ وimages/ وGrandDryClean/ وDina'sCorner/ وPOAC-Admin/.
5) ارفع التحديث إلى فرع اختبار أولاً، ولا تدمجه في الفرع المنشور قبل الاختبار.
6) بعد الرفع، افتح رابط GitHub Pages الخاص بـ welcome.html، ثم اختبر تحميل الأقسام والمنتجات والصور والفروع، وافتح السلة وأرسل طلبًا تجريبيًا حتى شاشة WhatsApp دون إرساله.
7) اختبر صفحة menu.html مباشرة أيضًا. حافظ على أسماء الملفات وحالة الأحرف والمسارات كما هي.

ما تم نقله محليًا لدينا:
- 8 أقسام، 71 سجل منتج (70 نشطًا وواحد غير نشط)، 4 فروع، 14 سجل صور مميزة.
- 91 ملف صورة فريدًا مستخدمًا بواسطة ملفات بيانات Dina.
- صفحات العملاء في الجذر تستخدم JSON محليًا ولا تحتاج Supabase للعرض.

مهم:
- صفحات الإدارة القديمة في Dina'sCorner/ ما زالت مرتبطة بـ Supabase في هذه النسخة.
- index.html وassets/app.js وGrandDryClean وPOAC-Admin ما زالت تحتوي وظائف متصلة بـ Supabase.
- لا تحذف config.js أو إعدادات الاتصال المشتركة الآن.
- لا تضع GitHub Personal Access Token داخل JavaScript أو HTML منشور.
- GitHub Pages لا يحفظ تعديلات JSON من لوحة الإدارة. تحرير البيانات يتطلب تحديث ملفات JSON والصور عبر Git، أو إعداد خدمة خلفية آمنة.
- لا تحذف مشروع Supabase أو نسخه الاحتياطية قبل اتخاذ قرار مستقل بشأن حسابات المستخدمين وسجل الطلبات وأي بيانات غير موجودة في ملفات JSON الحالية.
